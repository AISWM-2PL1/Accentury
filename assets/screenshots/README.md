# 스토어 스크린샷 (KAN-178)

Play 스토어·App Store에 올리는 스크린샷 네 장의 **원본 캡처와 생성 스크립트**가 여기 있다.
`build.py`가 기기 캡처 한 장에 같은 프레임(크림 배경 + 문구 두 줄 + 종이 조각처럼 앉힌 캡처)을 씌워
규격별 파생본을 만든다 — **생성물은 손으로 고치지 않는다.**

## 폴더 구성

```
build.py                   프레임 생성 스크립트
raw/android/<화면>.png     에뮬레이터 캡처 (Pixel 8, 1080×2400)      ← 사람이 넣는다
raw/ios/<화면>.png         시뮬레이터 캡처 (iPhone 17 Pro, 1206×2622) ← 사람이 넣는다
out/play/<화면>.png        Play 스토어 1080×1920            (생성물)
out/appstore-6.7/<화면>.png  App Store 6.7" 1290×2796       (생성물)
out/appstore-6.1/<화면>.png  App Store 6.1" 1179×2556       (생성물)
```

화면 id는 네 개 고정이다 — `01-intro` · `02-recording` · `03-vocab` · `04-result`.
`raw/`에 없는 화면은 검증표에 SKIP으로 찍고 넘어간다. 캡처를 한 장씩 채워 가며 돌려도 된다.

## 프레임

한 틀을 네 화면·세 규격에 똑같이 쓴다.

- 바탕은 크림 `#F3ECD9` 한 색이다. 앱 화면과 같은 종이 위에 캡처를 오려 붙인 것으로 읽히게 한다
- 위쪽에 문구 두 줄 — 헤드라인은 Jua 잉크 `#1C1A17`, 보조 줄은 Jua 작게 `#6B6459`. 가운데 정렬이고,
  프레임 폭의 88%를 넘으면 글자 크기를 줄인다(잘린 문구가 스토어에 걸리는 게 최악이다)
- 아래에 캡처. 둥근 모서리(캡처 폭의 5%) + 잉크 테두리 + `#CFC5AA` 오프셋 그림자 — `docs/wiki/design-tokens.md`
  §2의 Papercut 규칙(3px 4px 0)을 프레임 폭 비율로 옮긴 값이다
- `04-result`에만 캐릭터 스티커(`web/src/assets/characters/native.webp`, 경남 토박이)를 오른쪽 아래
  모서리에 걸쳐 놓는다. 그 파일이 없으면 스티커 없이 만든다(`assets/characters/build.py` 산출물이다)

캡처는 **전체가 다 보이는 크기**로 넣는다. 좌우 여백이 6% 이상이면 잘라내지 않는다는 뜻이라, 9:16
프레임(Play)에 20:9 캡처를 넣으면 좌우가 18%씩 비고 캡처는 프레임 폭의 64%가 된다. 그림 아래쪽이
잘려서 버튼이 사라지는 것보다 낫다고 봤다. 캡처가 더 길어져 폭이 프레임의 62% 아래로 떨어질 때만
폭을 62%로 키우고 아래를 프레임 밖으로 흘린다(`MIN_CAPTURE_W`).

Android 상태바·내비게이션 바는 **자르지 않는다.** Play가 허용하고, 자르기 시작하면 기기마다 기준이
갈린다. 크기만 맞춘다.

## 문구

`build.py` 맨 위 `CAPTIONS` 딕셔너리 하나에 다 있다. 여기만 고치고 다시 돌리면 세 규격에 한꺼번에 반영된다.

| 화면 | 헤드라인 | 보조 |
| --- | --- | --- |
| `01-intro` | 내 사투리, 몇 등급? | 3분이면 끝나는 경남 사투리 레벨 테스트 |
| `02-recording` | 말해보면 곡선이 그려져요 | 억양을 실시간 피치 곡선으로 |
| `03-vocab` | 이 말, 무슨 뜻일까? | 경남 토박이만 아는 단어 문제 |
| `04-result` | 5등급 중 당신은? | 결과 카드로 친구에게 공유 |

## 원본 캡처 만드는 법

**Android** (에뮬레이터 또는 실기기 — Pixel 8 계열 1080×2400 기준)

```
~/Library/Android/sdk/platform-tools/adb exec-out screencap -p > assets/screenshots/raw/android/01-intro.png
```

**iOS** (시뮬레이터 — iPhone 17 Pro 1206×2622 기준)

```
xcrun simctl io booted screenshot assets/screenshots/raw/ios/01-intro.png
```

캡처는 크기가 달라도 된다(스크립트가 비율을 지켜 맞춘다). 다만 세로 화면이어야 하고, 네 화면의
캡처 크기는 플랫폼 안에서 같은 값으로 맞추는 게 보기 좋다.

## 재생성

```
/Users/iseongju/accentury/.venv/bin/python assets/screenshots/build.py
```

폴더를 바꿔서 돌릴 수도 있다(임시 캡처로 배치만 확인할 때).

```
... assets/screenshots/build.py --raw <원본 폴더> --out <출력 폴더>
```

Pillow·numpy가 필요하다(위 venv에 있다). 끝에 규격 검증표를 찍는다 — 파일 존재·정확한 픽셀 크기·
알파 없는 RGB·모서리 색이 크림인지·8MB 이하. 하나라도 FAIL이면 종료 코드 1이고, SKIP만 있으면 0이다.

## 규격 (업로드 기준)

| 대상 | 크기 | 형식 | 비고 |
| --- | --- | --- | --- |
| Play 휴대전화 | 1080×1920 | 24비트 PNG 또는 JPEG, 알파 없음 | 16:9~9:16, 변 320px 이상 3840px 이하, 장당 8MB 이하. 2~8장 |
| App Store 6.7" | 1290×2796 | RGB PNG, 알파 없음 | 필수 규격 |
| App Store 6.1" | 1179×2556 | RGB PNG, 알파 없음 | 6.7"만 올리면 자동 축소되지만, 글자가 뭉개져서 따로 만든다 |

App Store는 두 규격 모두 세로 방향이고, 알파 채널이 있으면 업로드가 거절된다 — 검증표의 `RGB` 열이
그걸 본다.
