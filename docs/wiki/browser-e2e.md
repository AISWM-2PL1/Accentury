# 브라우저 E2E 설계 (KAN-181)

구현 기록 (2026-09-01). 웹 레이어에 실브라우저 검증 한 겹을 얹은 이유와 그 과정에서 정한
규칙들. **돌리는 법은 [web/README.md](../../web/README.md)가 정본이고, 여기는 왜 그렇게
만들었는지를 적는다.**

> **스택의 AI는 가짜 엔진이다 (2026-09-06, KAN-22 PR #87 리뷰 반영).** AI 서버가 채점 모델
> 전달본을 베이스로 하면서 개발 기계와 CI 러너에서 띄울 수 없게 됐고, 2026-09-05에 스텁
> (`ACCENTURY_AI_STUB_FAIL_ITEM`)과 `scripts/e2e-smoke-local.sh`가 사라졌다. 그러자 분석까지
> 가는 스펙이 돌릴 스택을 잃어, 같은 앱을 `ACCENTURY_AI_ANALYSIS_ENGINE=fake`로 띄우는 `ai`
> 서비스를 루트 compose에 되살렸다 (`ai/app/fake.py`, 실패 문항은 `ACCENTURY_AI_FAKE_FAIL_ITEM`).
> 아래 글의 "AI 스텁"은 그 가짜 엔진으로 읽으면 된다. CI job은 내린 채이고 스펙 파일은 남아
> 있다 - slim 이미지라 러너에서도 뜨므로 되살리는 것은 별도 결정이다.

## 왜 한 겹 더 두는가

vitest가 이미 51개 파일 757개 테스트로 컴포넌트 단위를 지킨다. 그런데도 브라우저를 띄우는
이유는 **jsdom에 없는 것들** 때문이고, 하필 시작 게이트가 그것을 전부 지나간다.

| jsdom에 없는 것 | 그래서 단위 테스트가 못 보는 것 |
|---|---|
| `getUserMedia` | 권한 게이트의 실제 갈래. 주입한 가짜 권한 함수만 본다 |
| `AudioContext` · `AudioWorklet` | 워클릿 → 리샘플러 → YIN이 실제로 이어지는가 |
| `location.href` 대입 | 화면 전환. 주입한 `navigate`가 받은 **문자열**까지만 본다 |
| 진짜 네트워크 | 세션 토큰이 문서 리로드를 건너 살아남는가, `/v0` 프록시가 닿는가 |

넷을 하나씩 흉내 내는 대신 **한 번 걸어 보면 전부 걸린다**는 것이 이 레이어의 값이다.

## 가짜 마이크

Chromium 실행 인자 셋이 한 덩어리다. 셋이 같이 있어야 "권한도 통과하고 무엇이 들리는지도
정해진" 상태가 된다.

```
--use-fake-device-for-media-stream    진짜 장치 대신 합성 장치
--use-fake-ui-for-media-stream        권한 대화상자 자동 승인
--use-file-for-fake-audio-capture=…   그 장치가 낼 소리를 파일에서
```

Playwright의 `permissions: ['microphone']`을 쓰지 않는다. 권한만 주면 장치가 없는 CI에서
빈 소리가 잡히는데, 우리가 확인하려는 것은 "권한이 있다"가 아니라 "목소리가 들어와서 판정이
난다"이기 때문이다.

**파일은 앱 자산을 그대로 참조한다** — `app/src/debug/assets/fake_mic.wav`(2.5초 "안녕하세요",
mono 16kHz 16-bit). 에뮬레이터의 `-PfakeMic`이 쓰는 것과 같은 파일이다. web/ 안에 복사본을
두지 않는 이유는 두 벌이 되면 한쪽만 갱신되기 때문이다. 앱과 웹이 같은 소리로 같은 점검을
통과해야 한쪽에서 통과한 것이 다른 쪽의 근거가 된다.

### 반복 재생 실측

문항 녹음이 2.5초를 넘기므로 파일이 끝나면 어떻게 되는지를 짐작으로 둘 수 없었다. 스트림의
rms를 9초 동안 0.28초 간격으로 재 봤다.

- 2.5초를 지나도 소리가 끊기지 않는다.
- 같은 봉우리(rms 0.31)가 3396ms와 5951ms에 반복 — **간격 2555ms가 파일 길이와 같다.**

→ Chromium은 파일 끝에서 처음부터 다시 재생한다. 파일을 길게 늘릴 필요가 없다.
끊기게 하려면 경로 뒤에 `%noloop`을 붙인다.

## 셀렉터 규칙

`getByRole`·`getByText`가 기본이다. 결과적으로 **`data-testid`를 한 개도 넣지 않았다** —
화면이 접근성 트리를 제대로 세워 두면 테스트용 표식이 필요 없다는 뜻이기도 하다.

### 이름 대조는 기본이 부분 일치다

`getByRole('button', { name: '녹음' })`은 **[재녹음]까지 잡는다**. 확인 단계에 두 버튼이 함께
있어 셀렉터 하나가 둘을 가리킨다. 버튼은 전부 `exact: true`를 붙인다.

### 화면의 상수를 import한다

문항 카드 캡션을 `/^1 \/ 10 · /` 같은 정규식으로 잡았더니 상단 진행 표시(`1 / 10 · 음성`)와
카드 배지(`1 / 10 · 이 문장을 읽어주세요`)가 **둘 다** 걸려 strict mode 위반이 났다. 해결은
`src/progress/itemBadge.ts`의 `itemCaption()`을 e2e에서 직접 불러 문자열 전체로 잡는 것이었다.

부수 효과가 하나 더 있다. 음성용·어휘용 캡션 두 개를 만들어 어느 쪽이 떴는지 보면 **대기와
유형 판정이 한 번에 끝난다** — 문항 순서를 스펙에 박지 않아도 된다.

다만 아무 모듈이나 끌어오면 안 된다. React 컴포넌트를 import하면 그 모듈이 딸고 오는 것들이
전부 Node 테스트 프로세스로 들어온다. 상수만 있는 순수 모듈(`introText.ts`, `itemBadge.ts`)만
쓰고, 버튼 라벨처럼 JSX 안에 사는 문구는 스펙에 문자열로 적는다.

### 눈에서 지운 요소

어휘 선택지의 라디오는 `1px + clip-path: inset(50%)`로 시각에서만 빠져 있다(`components.css`).
접근성 트리에는 남아 있어 `getByRole('radio')`로 잡히지만, 1px로 잘려 보통의 클릭 판정에는
걸리지 않는다. `check({ force: true })`로 넘긴다 — 클릭은 감싼 `<label>`이 받아 어차피 같은
선택으로 이어진다.

### 라벨이 바뀌는 버튼

어휘 제출 버튼은 상태를 따라 `다음`/`제출 중…`/`다시 시도`로 바뀐다. 이름으로 잡으면 재시도
갈래에서 조용히 못 찾는 셀렉터가 되므로 **"이 화면의 유일한 버튼"**으로 잡는다.

### 순서는 계약이 아니다

지금 정의(`gn-2026.08.1`)는 음성·어휘가 번갈아 나오지만 그건 정의의 사정이다. 스펙은 화면에
뜬 것을 보고 갈라(라디오 그룹이 있으면 어휘) 10문항을 돈다. 반대로 **개수는 계약이라**
단언한다 — 인트로가 상수로 약속한 음성 5 + 어휘 5(`introText.ts`)가 그대로 나와야 한다.

## 스택 두 상태와 대칭 스킵

AI 스텁은 `ACCENTURY_AI_STUB_FAIL_ITEM`으로 특정 문항을 반드시 실패시킬 수 있다. 완주 스펙은
그 설정이 **없어야** 통과하고 실패 갈래 스펙은 **있어야** 의미가 있다. 한 스택이 둘을 동시에
만족할 수 없다.

환경 변수 `E2E_FAIL_ITEM`을 신호로 삼아 두 스펙이 조건을 뒤집어 `test.skip`한다.

- 스펙이 스택 상태를 스스로 알아내는 길은 없다. AI의 `/internal/v0/health`는 `{"status":"UP"}`만
  주고 스텁 설정을 노출하지 않는다(실측).
- 노출하더라도 웹 스펙이 AI를 직접 부르는 것은 구조에 어긋난다 — 그 서버는 BE만 호출하는
  사설망 서비스이고, `E2E_BASE_URL`로 배포 환경을 겨눌 때는 닿지도 않는다.
- 환경 변수는 로컬·CI·staging에서 똑같이 동작하는 유일한 신호다. 이름을 새로 짓지 않고
  `E2E_FAIL_ITEM`을 쓴 것은 레포가 이미 그 이름을 쓰기 때문이다(`docker-compose.yml`,
  `scripts/e2e-smoke-local.sh`).

skip은 실패가 아니라 **"이 무대는 내 것이 아니다"라는 선언**이다. 조건부 분기를 한 스펙에
밀어 넣는 것보다 각자 자기 무대에서만 도는 편이 실패했을 때 원인이 분명하다.

## 지역 화면은 스펙이 아니라 헬퍼가 가른다 (KAN-202, 2026-09-11)

출신 지역 선택 화면은 빌드 변수 `VITE_REGION_SELECT`가 정확히 `'true'`인 번들에만 있다
(`web/src/region/regions.ts`) — staging은 켜고 prod는 변수 자체가 없다. 위의 `E2E_FAIL_ITEM`과
달리 이것은 **대칭 스킵으로 가르지 않았다.** 스택 상태가 아니라 화면 유무의 문제이고, 화면은
스펙이 직접 볼 수 있기 때문이다.

`startTest`가 [내 억양 테스트하기] 뒤에 지역 제목과 점검 제목 중 **먼저 뜨는 쪽**을 기다린다
(`regionHeading.or(voiceHeading)`). 지역 화면이면 라디오 하나(경남)를 고르고 [다음], 아니면
그대로 점검으로 간다. 빌드 변수를 읽지 않는 이유는 `E2E_BASE_URL`로 staging을 겨눌 때 스펙
프로세스의 환경이 번들과 아무 관계가 없기 때문이다 — 스펙에 주소를 두지 않아 같은 스펙이
로컬·배포 양쪽을 도는 원칙의 연장이다. 그래서 스펙 파일은 한 벌이고 켠 판·끈 판은 **같은
파일을 두 번** 돌린다.

두 순서가 중요하다.

- `.or()`로 먼저 기다리고 나서 `isVisible()`로 어느 쪽인지 본다. `isVisible()`은 기다리지
  않는 즉답이라, 먼저 부르면 권한 승인 직후의 빈 순간을 "지역 화면 없음"으로 읽는다.
- 지역 라디오도 어휘 문항과 같은 `.choice__radio`(1px + clip-path)라 `check({ force: true })`다.

"지나갔다"에서 끝내지 않는다. 세션 생성 요청을 `waitForRequest`로 따로 잡아 `postDataJSON()`을
보고, 지역 화면을 봤으면 `region === 'GYEONGNAM'`, 못 봤으면 `'region' in body === false`를
단언한다. 201 응답(`waitForResponse`)은 서버가 받아 줬다는 것만 말하고 무엇을 보냈는지는
말하지 않는다 — 꺼진 빌드가 "키 자체를 안 보낸다"는 AC는 요청 본문에서만 확인된다.

### 켜는 법과 `.env.local` 함정

로컬은 `VITE_REGION_SELECT=true npm run test:e2e`. `playwright.config.ts`의 `webServer.env`가
`VITE_REGION_SELECT: process.env.VITE_REGION_SELECT ?? ''`로 넘긴다. Playwright는 `env`를
부모 환경 위에 얹으므로(`...process.env, ...env`, 1.62.1 소스 실측) 셸 값을 넘기는 데는 이
줄이 필요 없다. 이 줄의 값은 **`?? ''`** 쪽에 있다 — Vite의 `loadEnv`는 `process.env`에 있는
키를 `.env.local`보다 우선하므로, 개발자가 화면 확인용으로 `web/.env.local`에
`VITE_REGION_SELECT=true`를 둔 채 E2E를 돌려도 빈 값이 그 파일을 눌러 끈 빌드가 뜬다.
그 줄이 없으면 그 기계에서는 끈 판이 영영 돌지 않는다. `VITE_API_BASE: ''`와 같은 모양이다.

## 동의 시트는 헬퍼가 걷는다 (KAN-197 2단계, 2026-09-13)

브라우저 단독 실행의 첫 방문에는 인트로 위에 맞춤형 광고 동의 시트가 덮인다
(`web/src/ads/adConsent.ts`). 막이 `position: fixed; inset: 0`이라 그대로 두면 [내 억양
테스트하기]가 **가려진 채로 남고**, Playwright의 actionability 검사가 클릭을 기다리다 시간
초과로 죽는다. vitest에서 아무 테스트도 깨지지 않은 것과 대비되는 자리다 — jsdom에는
hit-testing이 없어 `fireEvent.click`이 막을 뚫고 닿는다.

그래서 `startTest`가 `goto('/')`와 h1 확인 **직후에** `passAdConsentIfShown(page)`를 부른다.
시트가 있으면 「일반 광고만 보기」를 눌러 닫히기를 기다리고, 없으면 그냥 지나간다. 위의 지역
화면과 같은 원칙이다 — 스펙은 자기가 어떤 판을 열었는지 모르므로 빌드 변수가 아니라 화면에
뜬 것을 보고 간다. 셀렉터는 `adConsentText.ts`의 `AD_CONSENT_TITLE`·`AD_CONSENT_DENY`를
import한다 (셀렉터 규칙 「화면의 상수를 import한다」).

지역 화면과 다른 점이 하나 있다. 거기서는 `.or()`로 먼저 기다린 뒤 `isVisible()`을 보지만,
이쪽은 `isVisible()` 하나로 충분하다 — 부르는 쪽이 이미 h1을 기다렸고 시트는 그 h1과 같은
렌더에서 함께 그려지므로(`IntroScreen`이 둘을 한 번에 반환한다) 판정이 빈 순간에 걸릴 일이 없다.

**거부를 고르는 것이 계약이다.** 3단계 AC가 「동의 거부 시 비맞춤 광고만」이라 E2E가 도는 동안
맞춤형 광고 요청이 나가면 안 된다. 고른 값은 브라우저 저장소에 남지만 Playwright는 테스트마다
새 컨텍스트라 저장소가 비어 있어 **매번 다시 뜬다** — 한 번 고르면 그만인 헬퍼가 아니다.

`startTest`를 거치지 않고 인트로에서 직접 클릭하는 스펙도 같은 줄이 필요하다. 지금은
`smoke.spec.ts`(숫자 카드 확인 전)와 `mic-blocked.spec.ts`(두 테스트의 `goto` 직후)가 그렇다.

**실측 (3단계, 2026-09-13).** 백엔드 없이 도는 `mic-blocked.spec.ts`로 확인했다 — 2 passed.
헬퍼가 `isVisible()`로 조용히 지나쳤을 가능성을 가르려고 같은 판에서 일회용 스펙을 하나 더
띄워 시트가 **실제로 떠 있는지**까지 단언했고(`isVisible()`이 true, 「일반 광고만 보기」 클릭
뒤 `toBeHidden()`), 통과했다. 시트가 안 떴는데 헬퍼가 통과한 것이 아니라 떠 있는 시트를 걷고
지나간 것이다. 같은 스펙을 `VITE_ADSENSE_CLIENT_ID`·`VITE_ADSENSE_SLOT_ID`를 셸에 준 채로 한
번 더 돌려도 2 passed다 — 태그 변수가 있는 빌드가 시작 게이트를 깨지 않는다(KAN-197 AC 6).
Playwright가 `webServer.env`를 부모 환경 **위에** 얹으므로 셸의 값이 개발 서버까지 그대로
간다 (`playwright.config.ts`의 `VITE_REGION_SELECT` 주석과 같은 경로).

## 발견: 브라우저 단독에는 재녹음 복구가 없다

처음 겨눈 것은 "분석이 실패한 문항을 재녹음해 복구하고 완주한다"였는데, **그 길은 브라우저에
없다.**

`TestFlowScreen`이 브리지가 없으면 대기 화면에 `onRetake`를 넘기지 않는다 — 눌러도 네이티브 녹음
화면이 열리지 않아 아무 일도 하지 않는 버튼이 되기 때문이다. 버튼이 없으니
`AnalysisWaitingScreen`의 `hasActionableRow`가 거짓이 되고, 서버가 "사용자가 움직여야
한다"(409 `RESULT_RETAKE_REQUIRED`)고 말한 상황에 화면에는 누를 것이 하나도 없는 막다른
길이 된다.

v3를 실패시켰을 때 브라우저가 보여주던 화면(KAN-191 이전):

```
분석 중 8 / 10
여기서는 더 진행할 수 없어요
앱을 다시 시작해 테스트를 처음부터 진행해 주세요
1번 문항 완료 / 3번 문항 완료 / 5번 문항 다시 녹음이 필요해요 / 7번 문항 완료 / 9번 문항 분석 중
버튼: 없음
```

막다름 자체는 설계다 — 화면은 되살릴 방법이 없다는 사실을 숨기고 "다시 녹음해 주세요"라고
말하는 대신 할 수 있는 일을 알려준다(`AnalysisWaitingScreen`의 `deadEnd` 주석).

### 후속 티켓 후보 → 하나는 닫혔다

- ~~**안내 문구가 브라우저 사용자에게는 어긋난다.**~~ → ✅ **닫힘 (2026-09-08, KAN-191)**.
  "앱을 다시 시작해 테스트를 처음부터 진행해 주세요"는 앱 안에 있는 사람을 향한 말이었다.
  문구를 **"테스트를 처음부터 다시 진행해 주세요"**로 바꾸고, 그 아래 [다시 테스트하기]를
  실제로 놓았다 — 브라우저에서는 브리지가 없어 폴백(`goToIntro`)이 인트로로 되돌린다.
  같은 출구가 `FAILED`(재시도 불가 실패)에도 붙는다. 결정과 상태별 규칙은
  [ux-ui.md](ux-ui.md) §4-F가 정본이다. 그래서 위 화면의 마지막 줄은 이제
  `버튼: 다시 테스트하기 1개`이고, `retake.spec.ts`가 그 개수와 클릭 후 인트로 복귀까지 단언한다.
- **웹 단독 재녹음 통로 자체를 열지 검토.** 웹 녹음 패널(`WebVoiceRecorder`)이 이미 있으므로
  `onRetake`를 그쪽으로 잇는 것은 기술적으로 막혀 있지 않다. 다만 진행 상태를 특정 문항으로
  되돌리는 규칙이 새로 필요하다. **KAN-191이 이것까지 열지는 않았다** — 막다른 상태에서
  나가는 길을 준 것이지 그 자리에서 복구하는 길을 준 것이 아니다.

남은 후보와 별개로, 로컬에서는 어차피 복구되지 않는다. 가짜 엔진의 `analyze`가 `item_id`만
보고 실패시키므로(`ai/app/fake.py`) 같은 문항을 다시 올려도 같은 판정이 나온다. 재시도의
correlationId가 달라져도 마찬가지다.

### 실패 갈래를 돌리려면 CORS에 5174가 있어야 한다 (2026-09-08 실측)

`web/README.md`의 백엔드 기동 예시는 허용 출처로 5173만 적었는데(2026-09-11 KAN-202 3단계에서
5174와 `ai-token` 인자를 예시에 넣어 정정), Playwright는 **E2E 전용 포트 5174**에 개발 서버를
띄운다. 브라우저는 같은 출처라도 POST에 `Origin`을 싣고 Vite 프록시가 그 헤더를 그대로
넘기므로, 5174가 목록에 없으면 세션 생성이 **403**으로 끊긴다(`startTest`의 201 단언에서
죽는다). 기동 인자에 `http://localhost:5174,http://127.0.0.1:5174`를 함께 넣는다.

같은 예시에서 빠져 있던 것이 하나 더 있다 — `--accentury.analysis.ai-token`. compose의 `ai`가
`ACCENTURY_AI_INTERNAL_TOKEN`으로 `X-Accentury-Internal-Token`을 검사하므로(KAN-36) 백엔드를
호스트에서 띄울 때 같은 값을 넘기지 않으면 BE→AI가 401로 막혀 회로가 열리고, `full-run`이
분석 대기에서 멈춘다. 스모크는 세션 생성까지라 이 누락을 못 본다.

## 실측 수치

전부 macOS + 로컬 스택 기준. `--repeat-each=3` 반복에서의 편차를 함께 적는다.

| 항목 | 값 |
|---|---|
| 시작 게이트 통과 | 1.15~1.37초 |
| 목소리 점검 통과 | 0.98~1.73초 (듣기 상한 10초) |
| 10문항 완주 | 18.4~18.8초 (녹음 3초 × 5건 + 업로드 + 어휘 5건) |
| 분석 대기 | 2.30~2.82초 |
| 완주 스펙 전체 | 20.7~21.7초 |
| 실패 갈래 스펙 | 18.5~18.9초 |
| 마이크 갈래 스펙 | 0.3~0.6초 |

분석 대기가 2.3초로 짧은 것은 음성 문항이 업로드 즉시 분석되기 때문이다 — 마지막 어휘 문항을
푸는 동안 대부분 끝나 있다. 그래도 대기 화면이 반드시 관측되는 이유는 `/complete` 폴링이
최소 한 주기(800ms)는 돌기 때문이다.

**녹음 길이는 벽시계로 재지 않는다.** 화면의 경과 표기가 `00:03`에 닿기를 기다리는데, 그
숫자는 담긴 샘플 수에서 오므로(`WebVoiceRecorder`) `waitForTimeout(3000)`과 달리 "정말
3초어치 소리가 들어왔다"를 보증한다. 느린 기계에서 시간만 흐르고 오디오가 덜 찬 채로 넘어가
품질 게이트에 `TOO_SHORT`로 걸리는 일이 없다.

## 트러블슈팅

### `NotSupportedError: Not supported` — 마이크 거부를 만들 수 없다

가짜 마이크 플래그를 빼면 막히기는 하지만, 헤드리스 Chromium이 던지는 것은
`NotAllowedError`가 아니라 `NotSupportedError`다(실측). `microphone.ts`의
`DENIED_ERROR_NAMES`에 걸리지 않아 `denied`가 아니라 `unavailable`로 접힌다.

권한 거부 화면을 보려면 `addInitScript`로 `getUserMedia`를 직접 갈아 끼운다. `addInitScript`인
것이 중요하다 — 이 앱은 화면 전환이 문서 리로드라, 로드 뒤에 심으면 다음 문서에서 원래
함수가 되살아난다.

```ts
await page.addInitScript(() => {
  Object.defineProperty(navigator.mediaDevices, 'getUserMedia', {
    configurable: true,
    value: () => Promise.reject(new DOMException('e2e', 'NotAllowedError')),
  })
})
```

이름만 바꾸면 갈래가 갈린다: `NotAllowedError` → `denied`, 그 밖은 전부 `unavailable`.

### `strict mode violation: resolved to 2 elements`

셀렉터가 둘 이상에 걸렸다. Playwright는 아무거나 고르지 않고 에러를 낸다 — 애매함을 즉시
실패로 바꾸는 설계라, 엉뚱한 요소를 잡고 한참 뒤에 이상하게 실패하는 것보다 낫다. 위
"화면의 상수를 import한다"가 실제 사례다.

### `/complete` 409 봉투의 모양

`retakeItems`는 **최상위 필드**다. 클라이언트가 읽고 나면 `itemIds` 아래로 묶이지만
(`errorEnvelope.ts`의 `readErrorEnvelope`) 그건 파싱 뒤의 모양이라, 원문을 보는 스펙에서는
서버가 실제로 보낸 자리를 봐야 한다.

### "없음"을 단언할 때는 앵커를 먼저

`toHaveCount(0)`은 아직 안 그려진 것과 영영 안 그려질 것을 구분하지 못한다. 실패 갈래
스펙이 "버튼이 하나도 없다"를 확인하기 전에 막다른 길 문구가 뜨기를 먼저 기다리는 이유다.
순서가 곧 정확성이다.

## 범위 밖

- **브리지 경로**(앱 WebView + 네이티브). 재녹음 복구, 네이티브 녹음 화면, 스큐 게이트가
  전부 여기 든다. 브라우저에는 `window.AccenturyBridge`가 없어 재현할 수 없다.
- **실모델 AI**. 로컬·CI 스택은 언제나 스텁이라 점수를 범위로만 본다.
- **다중 브라우저**. Chromium 하나만 돈다. WebKit(iOS Safari)은 오디오 제약이 달라 별도
  조사가 필요하다.
