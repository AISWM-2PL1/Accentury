## 4. MVP 화면별 설계

### 전체 플로우

```
스플래시 → 온보딩(방언 지도) → 마이크 권한(맥락 요청)
 → 인트로(문항 수·소요시간) → [음성 문항 ↔ 어휘 문항] ×N (진척도)
 → 분석 대기(선분석으로 대부분 스킵) → 결과(캐릭터→점수→곡선) → 공유 / 재응시
```

### A. 진입

스플래시(로고+곡선 모티프, 1초 미만) → "내 사투리 레벨 테스트 시작" 단일 CTA. 로그인 화면 없음.
**근거**: 바이럴 유입의 호기심 반감기는 몇 초 — 로그인 벽이 전환율을 반토막 낸다. Hick: 첫 화면 선택지 1개.

### B. 온보딩 — 방언 지도

2단계 인터랙션 유지하되 역할 전환: 경남 활성("이번 테스트: 부산·경남 편"), 경북 잠금(🔒 "다음 지역 준비 중"). 스킵 가능.
**근거**: ① 기대 설정(어떤 사투리를 평가받는지 = 오류 예방의 시작) ② 잠긴 경북 = 재방문 훅. "확장은 데이터 추가"라는 아키텍처 원칙과 정합.

### C. 마이크 권한 + 음성 처리 고지

OS 팝업 전에 자체 화면 1장: "발음 분석에 마이크가 필요해요 · 음성은 분석 즉시 삭제돼요". **권한 거부 시 테스트 시작 불가**(음성 문항 건너뛰기 없음 — 2026-07-27 확정), 거부 상태에선 설정 딥링크로만 진행 가능.
**근거**: 맥락 없는 권한 요청은 거부율이 높고 Android는 2회 거부 시 재요청 불가. "즉시 삭제"는 KAN-23/27 사실 — 프라이버시 불안 선제 해소. (동의 화면 KAN-2 [범위 제외]와 법무 검토는 별개로 미해결)

- "다음" 즉시 업로드+분석(KAN-24 비동기 선분석): 다음 문항 푸는 동안 백그라운드 분석 → 마지막 대기 ≈ 0. 분석 응답 수신(∥재녹음∥문항 이탈) 즉시 기기 내 WAV 삭제(FR-DP-02) — 문항 완료 후 저장소 잔존 0건
- ~~나가기 좌상단 소형 + 확인 다이얼로그: Fitts 역이용(세션 소실 방지)~~ → ✅ **폐기 (2026-08-19, KAN-147)**: 테스트 중 이탈 버튼(녹음 화면 [나가기]·업로드 바 [테스트 종료])을 전부 제거. 근거 — 3분짜리 바이럴 테스트에서 이탈 버튼은 Goal-Gradient(진척도 = 이탈 방지 장치)와 상충하고, 현재 화면은 무디자인 하네스라 이탈·복구 UX는 KAN-39(업로드 상태 화면 디자인)에서 디자인과 함께 한 번에 정한다. 발단은 KAN-146 실기 확인에서 구현이 명세(확인 다이얼로그 + 세션 종료)와 달리 "오버레이만 걷고 같은 문항에 잔류"하는 막다른 순환이었던 것. **감수하는 것**: 녹음 화면에서 나갈 방법이 없다(`BackHandler` 없음 → 시스템 뒤로가기 = 액티비티 종료). 음성 바이트 폐기(FR-DP-02)는 사용자 조작 없이 `UploadViewModel.onCleared → clearAll`이 보장
- ✅ **업로드 실패 복구는 한 통로 (2026-08-25, KAN-147)**: 실패 직후 상태 바 [재시도]와 웹 [녹음 화면 다시 열기]가 같은 화면에 겹쳐, 후자로 새 녹음을 만든 뒤 전자를 누르면 같은 문항에 분석 잡이 둘 생기던 결함을 닫음. 규칙(B안, 리뷰 P2-1 반영) — (1) 전송 실패(`TransportError`)는 [재시도] 무제한 — 응답이 안 온 것이지 녹음 문제가 아니고(멱등 키 덕에 서버가 이미 받았을 수도), 잠깐 끊긴 사용자의 녹음을 잃게 하는 건 회복 불가라서. 문구는 `net.TransportFailure`(Offline/ServerUnreachable/Timeout/Unknown)로 가름 (2) 서버가 녹음 자체를 거절한 코드(`UploadManager.RERECORD_CODES` = AUDIO_TOO_LONG·TOO_LARGE·TOO_QUIET → `Failed.rerecord`)만 `TestFlowController.onUploadGivenUp`이 시도를 버리고 `Recording(start, afterUploadFailure=true, failureMessage=서버문구)`로 녹음 화면을 자동 재개(권한 게이트·회전을 거쳐도 사유 유지). 그 외 재시도 불가 거절(SESSION_EXPIRED·RATE_RETAKE_EXCEEDED 등)은 서버 문구를 단 실패 행으로 남겨 자동 루프·사유 은폐를 막음 — 웹은 결과를 못 받아 그 문항 대기 화면에 멈춰 있으므로 네이티브가 덮어도 진행이 어긋나지 않음. 녹음 중이면 화면은 건드리지 않고 폐기만 (3) 같은 문항의 새 녹음이 등록되면 앞 시도는 폐기(`onRecordingFinished` 반환값 → `discard`) → **문항당 살아 있는 시도 1개**. 웹 [녹음 화면 다시 열기]는 네이티브가 결과 없이 돌려보낸 경우(PCM 없는 제출·프로세스 복원으로 시도가 걷힌 경우)의 재진입 통로로만 남음

### E. 어휘 객관식 (WebView)

질문 + 선택지 2~4개 카드, 탭 즉시 다음 문항. **정답 여부 무표시**.
**근거**: KAN-15 API 계약(중간 정답 미반환)이자 UX 결정 — 중간 피드백은 몰입 파괴 + 재시도 욕구 유발. 결과 서스펜스를 끝까지 보존. 음성↔어휘 교차 배치로 발화 피로 리듬 조절.

### F. 분석 대기

선분석 덕에 대부분 스치는 화면. 남으면: 곡선이 그려지는 애니메이션 + 단계 카피 순환("억양 곡선 추출 중 → 원어민 분포와 비교 중 → 등급 계산 중"). 상태 확인은 **폴링**(서버가 간격 조절, SSE 미사용, 최대 60초 — 2026-07-27 확정). 10초 넘으면 안심 문구로 전환, 60초 초과 시 KAN-14 복구 화면.
**근거**: Labor Illusion — 카피가 실제 파이프라인과 일치하므로 연출이 아님. 10초 = Nielsen 주의력 한계(안심 문구 전환점), 60초 = 폴링 상한(회의 확정).

### G. 결과 화면 (절정)

공개 순서 강제: ① 캐릭터/티어 리빌(0.8초 애니메이션) → ② 억양·어휘 점수 카운트업 → ③ 내 곡선 vs 기준 곡선 비교 그래프 → ④ 하단 고정 `[카카오로 공유]`(Primary) `[다시 테스트]`(Secondary)

**결정 근거**:
- 캐릭터 먼저: 정서적 보상 > 인지적 정보. 채점 프레이밍 "재미/엔터" 선택 = 바이럴 MVP 권고와 일치
- 점수 2개만: KAN-25가 억양·어휘 0~100만 반환. 그 이상 노출은 인지 부하 + 미완성 채점 두뇌에 대한 과잉 약속
- 곡선 비교 3순위: "왜 이 등급인지"의 시각 증거 = 납득감 + 스크린샷 자체가 광고
- 공유 Primary: MVP 성공 지표는 완주가 아니라 공유→유입 루프

### H. 공유 카드

캐릭터 + 티어명 + 곡선 모티프 + 도발 카피("나 사투리 호소인이라는데, 니는?") + 앱 링크 이미지 1장. 카카오톡 우선(KAN-30), 시스템 시트 폴백. 링크는 미설치자를 웹 테스트(KAN-31)로.
**근거**: 공유 심리 = 정체성 표현 + 도발. 카드만 봐도 3초 내 앱 이해. 곡선 = Von Restorff의 "기억되는 하나".

### I. 오류·엣지 상태

| 상황 | 처리 | 근거 |
|---|---|---|
| 권한 거부 | 가치 재설명 + 설정 딥링크 | 2회 거부 시 OS 재요청 불가 |
| 발화 없음/짧음 | 제출 전 클라이언트 차단, 비난 없는 카피 | 즉시 폐기 → 서버 재시도 불가 |
| 분석 실패(FAILED) | 해당 문항만 재녹음, 전체 초기화 금지 | 매몰 진행 보호 |
| 네트워크 끊김 | 로컬 상태 유지 + 재시도, idempotencyKey로 중복 안전. 음성 업로드는 [재시도] 무제한 + 원인별 문구, 자동 재녹음은 서버가 녹음을 거절한 경우만(§D, KAN-147 B안) | KAN-28 계약 |
| 결과 만료 | "결과가 만료됐어요" + 새 테스트 CTA | 결과는 24시간만 보관(2026-07-27 확정) |

## 5. 비주얼·모션·접근성 최소선

- 모션: ease-out 100~300ms. 결과 리빌만 예외적으로 길게(절정 연출). reduced-motion 대응
- 대사 카드 24sp 이상 — 발화용 텍스트는 가독성이 기능
- 터치 타겟 최소 48dp, 텍스트 대비 4.5:1
- 컬러: 곡선용 시그니처 색 1개 + 중립 배경 (곡선이 주인공)

## 6. 구현에 필요한 기술 (Kotlin 외)

Jetpack Compose(상태관리·테마·Navigation-Compose·Canvas·애니메이션), ViewModel/StateFlow, Room(오답노트·북마크), DataStore(설정), Retrofit multipart(오디오 업로드).

과소평가 주의 영역: 공유 카드 이미지 생성, WorkManager 푸시. (3-provider OAuth·Billing은 MVP 제외로 해소)

**추천 학습 순서** (인프런): Jetpack Compose 입문(오준석) → 코틀린 코루틴 완전 정복(조세영) → 서버 연동

## 7. 화면별 네이티브 / WebView 분담

**실시간 오디오·시각화는 네이티브 필수, 콘텐츠·통계·정적 화면은 WebView.** (비율 네이티브 65~70% / WebView 30~35%)

| 화면/기능 | 방식 | 이유 |
|---|---|---|
| 스플래시·(후속)로그인 | 네이티브 | 소셜 SDK 네이티브 필수, 첫인상 반응성 |
| 온보딩·권한 요청(마이크) | 네이티브 | OS 권한 API는 네이티브만 |
| 홈(학습 경로·스트릭·XP, 후속) | 네이티브 | 앱 뼈대, 애니메이션 반응성 |
| 판정 테스트 — 문장 제시 | 네이티브 | 녹음과 한 화면 |
| 🎙️ 녹음·오디오 캡처 | **네이티브 필수** | AudioRecord/AVAudioEngine, 원시 PCM |
| 📈 실시간 피치 곡선 | **네이티브 필수** | 초당 수십 프레임, WebView는 버벅임 |
| 결과 화면 — 억양 그래프 비교 | 네이티브 | 녹음 직후 즉시 전환, 핵심 경험 |
| 결과 공유 카드 생성 | 네이티브 | 이미지 생성·시스템 공유 시트 |
| 어휘 객관식 문항 | WebView | 인터랙션 단순, 콘텐츠 자주 변경 (KAN-13) |
| 테스트 인트로·진행·대기 | WebView | KAN-11·14, 콘텐츠성 화면 |
| 연습 대사 콘텐츠 목록/상세 (후속) | **WebView** | 앱 심사 없이 콘텐츠 반영 |
| 학습 통계·성장 리포트 (후속) | **WebView** | 실시간 아님, 웹 차트 |
| 프로필·설정 (후속) | 네이티브 | 계정·알림·구독 OS 연동 |
| 공지·이벤트·도움말·약관 | **WebView** | 정적 웹 콘텐츠 |

**착수 순서**: (1) 전부 네이티브, 특히 **녹음 + 실시간 피치 곡선**부터(앱의 심장이자 최난관) → (2) 대사 콘텐츠 30개 넘으면 목록만 WebView 분리 → (3) 통계·리포트 붙일 때 WebView 확대.
